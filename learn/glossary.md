# Glossary

## A

**Abstract Syntax Tree (AST)** — hierarchical representation of the syntactic structure of code. Each node of the tree represents a language construct (class, method, expression, etc.).

**Annotation** — metadata that can be added to classes, methods, fields or parameters. Used by frameworks such as Spring and JPA.

**ASM** — Java library for generating and transforming JVM bytecode. Used by the Kof compiler to generate `.class`.

**Bytecode** — intermediate representation of the program that the JVM executes. Generated by the compiler.

## C

**Cast** — explicit conversion from one type to another. In Kof: `valor as Tipo`.

**Checked Exception** — exception that must be declared on the method or handled with try/catch. Example: `IOException`.

**Class Loading** — the JVM's process of loading a `.class` file and making it available for execution.

**Compiler** — program that translates source code into bytecode. The Kof compiler translates `.kf` into `.class`.

**Constant Pool** — table of constants inside a `.class` file containing strings, class names, methods, etc.

## D

**Debug Adapter Protocol (DAP)** — debugging protocol that `kof debug`
implements (MVP, JVM target): breakpoints by Kof line, stack trace with
Kof functions/lines, continue, disconnect — the programmer debugs Kof code,
never the backend artifact.

**Desugaring** — transformation of syntactic sugar into more basic constructs. Example: `test "nome" { }` becomes a function + synthesized runner.

**Diagnostic** — error or warning message generated by the compiler.

**Domain Model** — representation of the problem's concepts in code.

## E

**Erasure** — process of removing generic type information at runtime. `List<String>` becomes `List` in bytecode.

**Expression** — code that produces a value. Example: `2 + 3`, `"olá"`, `user.name()`.

**Expression Body** — concise way to define a function: `Int dobro(Int x) = x * 2;`

## G

**Garbage Collection (GC)** — automatic process of freeing unused memory. The JVM does this.

**Generic** — type parameterization mechanism. Example: `class Caixa<T>`.

**GraalJS** — embedded JavaScript engine that Kof uses to run the KofJS
target (`kof run --target=js`) without depending on Node.js.

## K

**Kof IR** — Kof's single intermediate representation: the same frontend generates the
IR and the backends (JVM, Native x86-64/riscv64/aarch64, KofJS, KofC) consume it — `intention->Kof->frontend->IR->backend->runtime` (0.5.0-beta, Target separation).

**KofFormatter** — formatter of `kof fmt` (31/08): formatting via the real parser
(`KofFormatter`), idempotent.

**kof.web** — native web stack (0.5.0-beta): `web.app()` + routes
(`get/post/put/delete/patch/options` + `ws` WebSocket + `sse` SSE — 30/08),
middleware `app.use { }`, `status(código, body)` + `headerSet`, HTTP engine
generated inside the program runtime (no container). JVM; `WEB002` on Native.

**kof.http** — HTTP client (JVM+JS, via `Java HttpClient` interop on JS):
`http.get/post/put/delete/patch/options` + `timeout`/`retry`/`circuit`
(30/08). Native reports `HTTP002`.

**kof.security** — stdlib security layer (JVM/Native/JS, 31/08):
`passwords` (PBKDF2-HMAC-SHA256 600k), `crypto` (SHA-256/512, HMAC, AES-GCM),
`jwt` (HS256, sig/exp/iss/aud), `secrets`, `security` (constant-time,
rateLimit, session, apiKey), `auth` (web context). Gaps `SECN00x`
documented (e.g.: AES-GCM on JS).

**kof.db / kof.orm** — persistence (JVM: JDBC H2/MySQL/PostgreSQL + SQLite;
Native: SQLite via `.so` + MySQL WIP; JS: untyped (16/09), `query<T>` typed = `DB002`): `db.connect/execute/query`
+ `transaction {}`; ORM with declarative `entity` (CRUD, `where`, `page`,
`migrate`, MongoDB; native `ORM001`, JS CLOSED 18/09).

**KofC** — `kof c <file.c>` : compiler of a C subset (`int` globals, `void` funcs, `if`/`while`/`*(int*)`/`&`) → native-only x86-64 ELF (0.5.0-beta, Target separation).

**KofJS** — Kof's `js` target: generates ES Modules (ECMAScript 2022+) from the
Kof IR (JVM+JS for `kof.http`, HTTP002 Native). See `learn/37-kofjs.md`.

**KofScript** — `kof script <file.ks|kf>` + `kof repl` : direct execution; top-level `var`/`val` become persistent `KofScriptGlobals` (there is NO `let`/`const` — JS sugar removed 06/09), `--watch` re-executes; jvm/native/js targets (0.5.0-beta).

**String?** — basic nullable type (0.5.0-beta): `String? x = get(k); if (x != null) x.length()` (null reaches `T?` only via API — the `= null` literal is SEM048 since 10/09).

**Pattern matching** — `switch (o) { case String s: ... case Point(x,y): ... }` with type pattern + destructuring (0.5.0-beta, JVM/Native/JS).

**Free-list GC** — Native allocator `kof_free_head` (0.5.0-beta): reuses `mmap` via free-list, GC mark-sweep pending.

**kof_db / MySQL** — `kof_db` (JVM: JDBC/SQLite/MySQL/PostgreSQL/MongoDB; Native: SQLite via `.so` + MySQL wire protocol WIP with SHA-1 auth) (0.5.0-beta).

**Target separation** — `Target {JVM,NATIVE,NATIVE_RISCV64,NATIVE_AARCH64,JS,ANDROID}` + `parseTarget native.risc/arm` (`Target.nativeArch()`).

**kof.ui** — UI platform: `Color`, `Theme`, `Palette`, `Window`, `Label`,
`Button`, `Input`, `Column`/`Row`, `View`+`Style`, `Component` (lifecycle
`onMount`/`onDispose`) and **Router** (Phase 7, 31/08: `route/go/replace/
back/forward/current/param/depth`). Rendering is KofJS (native webview
`kof-webview` with WebKitGTK or browser); on the JVM/Native targets the handles are
no-ops. See `learn/35-kof-ui.md`.

**kof-webview** — native shell (embedded WebKitGTK, Linux) that opens the
interactive KofJS application; `kof run --target=js` waits for the window to close.

## I

**IIFE (Immediately Invoked Function Expression)** — function executed immediately after being defined.

**Immutability** — property of an object that cannot be changed after creation. Records are immutable.

**Inference** — the compiler's ability to deduce the type automatically. `var x = 42` infers `Int`.

**Intermediate Representation (IR)** — representation between the AST and bytecode. Lower than the AST, higher than bytecode.

**Invocation Target** — method that will be called by an `invoke*` instruction.

## J

**JIT (Just-In-Time)** — JVM compiler that converts bytecode into native machine code at runtime.

**JVM (Java Virtual Machine)** — virtual machine that executes bytecode. Kof runs on the JVM.

## L

**Lexer** — compiler phase that converts text into tokens.

**Lowering** — process of transforming high-level constructs into lower constructs. Example: records become classes with fields and methods.

## M

**Metadata** — data about data. In the bytecode context: information about types, annotations, line/column, etc.

**Method Descriptor** — string that describes a method's signature. Example: `(II)V` for `void m(int, int)`.

## P

**Parser** — compiler phase that converts tokens into an AST.

**Pattern Matching** — mechanism to check whether a value matches a pattern and extract data from it.

**Primitive Type** — fundamental JVM type: `int`, `long`, `float`, `double`, `boolean`, `byte`, `short`, `char`.

## R

**Record** — immutable class generated automatically. In Kof: `record Point(Int x, Int y)`.

**Reference Type** — type that references an object on the heap. Example: `String`, `User`, `List`.

**Reflection** — ability to inspect and modify program structures at runtime.

## S

**Sealed Class** — class that restricts which classes can inherit from it.

**Statement** — instruction that performs an action. Example: `return x;`, `if (c) { ... }`.

**Static Type Checking** — type checking done by the compiler before execution.

**Symbol Table** — data structure that stores information about identifiers (names of classes, methods, variables).

## T

**Token** — minimal lexical unit. Example: `record`, `Point`, `(`, `Int`.

**Type Erasure** — removal of generic type information at runtime.

**Type System** — set of rules that define how types interact.

## V

**Value Type** — immutable type that represents data. Records are value types.

**Virtual Thread** — lightweight thread managed by the JDK. Available since Java 21.
