# 33 — Versioning and Releases

> **Kof 0.5.0-beta — Sep 2026**

## Format

```text
MAJOR.MINOR.PATCH
```

- `X` — Major release
- `Y` — Major fix / significant evolution
- `Z` — Bugfix (**the little dot of shame**)

PATCH is the *little dot of shame*: bugfixes, corrections, regressions and
small adjustments without any relevant architectural change.

## Beta Stage (0.5.0-beta)

Kof moved from `0.0.x` (Alpha) to `0.2.6-beta`. Each release carries the suffix:

```text
0.5.0-beta
```

Nothing is called stable. The evolution was: Alpha → Beta (0.2.6-beta, Sep 2 2026; today 0.5.0-beta) → Release Candidate → Stable. The `intention->Kof->frontend->IR->backend->runtime` chain holds for all of them.

Official targets in 0.2.0: `jvm`, `native` (x86-64), `native.risc` (riscv64), `native.arm` (aarch64), `js` (KofJS), `kofc` (KofC C subset native-only). Target separation already in the `Target` enum.

## Single source of truth

The version lives in `VERSION` (repository root). `scripts/bump-version.sh`
synchronizes:

```text
VERSION (0.5.0-beta) → pom.xml (`<revision>`) → dev/kof/version.properties (packaged)
```

Never edit versions scattered across files — the pipeline handles that.

## Automatic release

Each commit on `main` generates the next version, in two jobs
(`.github/workflows/release.yml`):

```text
commit → CI ()
       → test-and-bump (Ubuntu)
            ├─ mvn clean package (gate) + golden + integration
            ├─ version bump (scripts/bump-version.sh)
            ├─ changelog section → CHANGELOG.md
            └─ commit + push of the bump ([skip ci]) — exports the SHA
       → package-and-release (matrix: 3 runners)
            ├─ checkout of the BUMP COMMIT (not the trigger one)
            ├─ sanity check: VERSION of the checkout == release version
            ├─ scripts/package.sh --jdk
            └─ GitHub Release per platform
```

- one release **per platform**: `kof-<v>-linux-x86_64`,
  `kof-<v>-macos-arm64` (Apple Silicon), `kof-<v>-windows-x86_64`
  (there is no `macos-x86_64`);
- `main` never points to a state that does not compile;
- a broken release is never published;
- artifacts: `kof-<version>-<os>-<arch>.tar.gz`/`.zip` + `SHA256SUMS` +
  `kof-cli-<version>.jar`;
- changelog generated by `scripts/changelog.sh` from the commit convention
  (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `build:`,
  `tooling:`), inserted into `CHANGELOG.md` at the `NEXT-RELEASE` marker.
- Native free-list GC and MySQL via `kof_db` entered the 0.2.0 changelog as runtime features, not language features.
