# Documentação bilíngue (EN / PT-BR)

O Kof entrega a documentação em **dois idiomas no mesmo repositório**. Todo
documento existe como um par:

| Caminho | Idioma | Papel |
|---|---|---|
| `X.md` | Inglês | canônico, o que o GitHub mostra, padrão em qualquer máquina cujo locale não seja português |
| `X.pt_BR.md` | Português | a frente em português |

A primeira linha de todo documento é o seletor de idioma:

```markdown
[English](X.md) | [Português](X.pt_BR.md)
```

## Como o idioma é selecionado

O `scripts/docs-lang.sh` lê `LC_ALL` → `LC_MESSAGES` → `LANG` → `LANGUAGE` e
resolve o idioma da máquina: qualquer valor começando com `pt` é português;
qualquer outro (inclusive vazio) é inglês.

- Em uma máquina **portuguesa**, o hook versionado `post-checkout` /
  `post-merge` copia `X.pt_BR.md` sobre `X.md` e o marca como `skip-worktree`,
  então a árvore mostra português **e continua limpa**. O blob commitado é
  sempre o canônico em inglês.
- Em **qualquer outra** máquina, o hook restaura o canônico em inglês a partir
  do índice.
- O `pre-commit` restaura o inglês canônico antes de todo commit, então um
  commit nunca captura a sobreposição portuguesa por acidente.
- O `post-commit` reaplica o idioma da máquina em seguida.

Os hooks são versionados em `.githooks/`. Ative-os uma vez por clone:

```bash
scripts/docs-lang.sh install      # define core.hooksPath=.githooks e aplica
```

## Comandos

```bash
scripts/docs-lang.sh status       # idioma da máquina, cobertura, nº de pares
scripts/docs-lang.sh check        # gate: todo doc tem par e seletor
scripts/docs-lang.sh check --strict   # idem, sai com 1 em qualquer lacuna
scripts/docs-lang.sh list --missing   # canônicos ainda sem PT
scripts/docs-lang.sh show README.md   # imprime o doc no idioma da máquina
scripts/docs-lang.sh restore      # força o inglês canônico em tudo
scripts/docs-lang.sh apply pt     # força a sobreposição em português
```

## Regras para quem escreve

1. **Nunca traduza inline nos dois arquivos e deixe os dois divergirem.**
   Edite a frente que você domina; atualize a contraparte no mesmo commit.
2. **Mantenha o seletor como a primeira linha** de todo documento.
3. **Links internos apontam para o `.md` canônico.** O hook resolve para o
   idioma da máquina automaticamente; não fixe links `.pt_BR.md`, exceto no
   seletor.
4. **Código, comandos, identificadores e código-fonte Kof nunca são
   traduzidos** — só prosa, títulos e rótulos de tabela.
5. Um documento ainda não traduzido não tem par `.pt_BR.md`; o `check` o
   reporta como lacuna até que tenha.
6. **Documentos vivos** (`AGENTS.md`, `DOING.md`, `CHANGELOG.md`,
   `docs/status.md`, `docs/bugs-and-gaps/known-bugs.md`,
   `docs/bugs-and-gaps/conformance-matrix.md`,
   `docs/architecture/IMPLEMENTATION-UNIVERSAL-PLATFORM.md`) mudam a cada commit de
   qualquer lane. Edite a frente em português (`X.pt_BR.md`) e espelhe a mudança
   no canônico em inglês (`X.md`) **no mesmo commit**; após um `pull`, rode de
   novo `scripts/docs-lang.sh apply` numa máquina portuguesa e reconcilie o par
   antes de commitar. Esse drift é inerente — o conflito de rebase no
   `known-bugs.md` de 14/09 veio exatamente dele.
7. **Pausa/retomada:** `scripts/docs-lang.sh pause` congela a sobreposição
   enquanto uma tradução em massa está em curso; `resume` a reativa.
